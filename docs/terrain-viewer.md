# Terrain viewer notes

The 3D viewer uses the real output rasters generated by the inference pipeline. It does not derive geometry from the preview PNG; the project fetches the real numerical output and generates the mesh from it.

## How the viewer is fed

The frontend resolves AI output URLs via `resolveAiUrl()` from `client/src/services/api.js`. For a completed project, the app typically loads:

- the depth preview image
- the raw disparity `.npy` output
- the calibrated elevation output when present

The actual viewer behavior depends on whether the project is relative-depth only or metric-calibrated.

## Interpretation rules

- uncalibrated projects: the terrain is based on a relative-depth scale and is unitless
- calibrated projects: the surface is mapped using metric elevation when the validation checks support it

This distinction is important because the numerical output is not physically meaningful unless the calibration step succeeded.

## 3D interaction model

The viewer is based on the browser-controlled 3D canvas and should be treated as a visualization tool for exploring the generated terrain surface. It is not a measurement-grade geospatial analysis platform.

The code uses the source image as a visual texture where appropriate and builds the mesh from the inference raster. This means the 3D surface remains a derived interpretation of the model output, not a direct measurement of the scene.

## Current caveat

The repository contains the viewer logic and the supporting data flow, but actual runtime quality must still be verified by loading a real project and inspecting the generated mesh and outputs in the browser.
